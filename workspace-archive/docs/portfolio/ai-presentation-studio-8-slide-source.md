AI Presentation Studio｜把中文项目材料变成可编辑演示

## 项目介绍

AI Presentation Studio 是一款面向不懂 HTML/CSS、需要把中文产品项目材料做成演示文稿的 Windows 本地网页产品。用户只需粘贴材料并选择模板，本机 Codex 即可生成完整 HTML 演示；生成后可以在安全预览中修改现有文字与普通内容图片，保存并重新打开，最后导出自包含 HTML 与 PDF。项目以一周 MVP 为约束，通过技术原型、纵向切片、公开界面验收和真实模板资格测试，逐步降低生成稳定性、编辑保真、失败恢复与文件交付风险。当前 5 个首发模板已在本机、当前代码和所测材料下分别完成一次真实资格验收，下一步是用这份真实项目材料完成最终演示验证。

## 演示设定

- **目标受众**：产品经理面试官、AI 产品从业者。
- **演示时长**：约 5 分钟。
- **页数**：按下面的 8 页结构组织，不增加目录页。
- **推荐模板**：Cobalt Grid。
- **选择依据**：该模板在 Issue #6 的一次真实资格运行中输出 8 页，并完成生成、安全预览、跨页编辑、保存重开、离线 HTML 与逐页 PDF；资格记录没有发现 Cobalt Grid 专属阻断问题。以上只代表当前本机和所测链路，不是长期稳定性承诺。
- **视觉原则**：突出“材料 → 可信交付”的过程；使用流程图、对比、时间线、证据矩阵和产品界面示意，每页至少包含一种非文字视觉元素。
- **事实边界**：不得虚构效率提升、用户数量、满意度、市场份额或长期稳定率；明确区分已验证能力与下一步验证。

## 第 2 页｜问题：真正困难的不是生成一页，而是交付一套能继续工作的演示

**页面主张**

有内容，不等于能做出一套可放心修改和交付的演示。

**三类痛点**

1. **生成前**：不懂 HTML/CSS，也不知道怎样把完整设计要求交给 AI。
2. **生成后**：标题、字号、颜色、图片位置等小问题仍需要修正，但结果常常难以继续编辑。
3. **交付时**：保存、重新打开、导出和失败恢复不清楚，用户不敢把真实材料交给流程。

**结论**

首版要解决的不是“再做一个一键生成器”，而是把生成、修正和交付连成一条可信流程。

**画面建议**

使用“生成前—生成中—生成后”三段断裂流程，右侧以一条完整闭环作为对比。

## 第 3 页｜聚焦：先服务一个真实用户，先跑通一条完整链路

**首个用户**

产品作者本人：不懂 HTML/CSS，需要把中文产品项目材料做成求职展示演示。

**一周 MVP 的唯一场景**

粘贴中文材料 → 选择模板 → AI 生成 → 轻量编辑 → 保存并重新打开 → 导出 HTML / PDF。

**首版主动暂缓**

- PPTX 导出

**页面结论**

范围小，不代表只是做一个页面；首版仍然覆盖从真实输入到可交付成果的完整闭环。

**画面建议**

用“范围内 / 暂缓”双栏对比；范围内只保留一条粗线流程，暂缓项使用低对比度卡片。

## 第 4 页｜方案：把 AI 生成放进一条可理解、可恢复的产品流程

**七步主流程**

1. 粘贴中文项目材料。
2. 从 5 个视觉模板中选择一个。
3. 本机 Codex 生成完整、自包含的 HTML 演示。
4. 在受限环境中安全预览和翻页。
5. 修改现有文字；拖动并等比例缩放普通内容图片。
6. 保存、返回首页并重新打开继续工作。
7. 导出可独立翻页的 HTML 和逐页 PDF。

**两条保护边界**

- 背景、Logo、SVG 和模板装饰保持锁定，避免误改视觉体系。
- 生成失败或取消时不展示残缺结果，保留源材料和模板，允许重试。

**画面建议**

使用一条横向七步流程，安全预览与失败恢复作为上下两条“护栏”包住主流程。

## 第 5 页｜取舍：四个决定，让一周 MVP 真正能落地

**决定一｜完整 HTML，而不是先发明统一内容格式**

完整 HTML 生成更慢、Token 用量更高，也可能产生结构漂移；但它能最快保留模板的完整视觉和翻页能力，适合首周先证明完整链路。

**决定二｜选择性复用，而不是复制整个 Open Design**

只复用来源和许可证清楚的模板；编辑能力由 GrapesJS（网页可视化编辑器组件）承担，避免把无关平台复杂度带入首版。

**决定三｜先做 Grove 纵向切片，再扩展到 5 个模板**

先让一个模板从生成一直走到导出，再让其他模板进入同一验收合同，尽早暴露模块组合问题。

**决定四｜本地优先，并把安全与恢复写进主流程**

使用本机已登录的 Codex，不增加账号、API Key 和云端计费系统；同时限制预览能力、单次只运行一个生成任务，并保护删除与重新生成。

**画面建议**

四张决策卡，每张都包含“选择 / 代价 / 为什么现在值得”三行，而不是只写技术名称。

## 第 6 页｜验证：不是先把功能堆满，而是逐个消除最危险的不确定性

**阶段一｜技术原型**

验证 Open Design 模板、Codex 生成和 GrapesJS 编辑可以组合工作，并暴露完整 HTML 的耗时、Token 和结构漂移代价。

**阶段二｜Grove 正式纵向切片**

依次完成生成、安全预览、编辑、保存重开、失败与取消恢复，以及 HTML / PDF 导出。

**阶段三｜真实材料人工验收**

自动测试全绿后，真实五页项目仍暴露背景与间距丢失、动画文字不可见、后续页面难编辑、完成编辑后预览异常等问题。

**阶段四｜把反馈变成回归标准**

将真实问题拆成可重复测试，修复样式保真、多页导航、预览加载和 PDF 分页，并确保修复不会破坏已有流程。

**阶段五｜五模板资格验收**

5 个首发模板分别通过一次真实 Codex 全链路；依赖外部 Chart.js 的 Retro Windows 被淘汰，没有为了保留候选而放宽安全规则。

**页面结论**

“测试通过”不是终点；真实材料和人工反馈会继续改写验收标准。

**画面建议**

使用从“未知”走向“证据”的五阶段阶梯；把人工发现的 4 类问题做成醒目的转折点。

## 第 7 页｜证据：当前已经证明什么，还没有证明什么

**已验证，且只限当前本机与所测链路**

- 5 个首发模板：Grove、Blue Professional、Biennale Yellow、Cobalt Grid、Studio。
- 每个模板各完成一次真实 Codex 资格运行。
- 资格链路覆盖生成、安全预览、跨页文字与普通图片编辑、锁定边界、保存重开、离线 HTML 和逐页 PDF。
- 不同模板的真实资格结果为 8–12 页。

**这次为什么选择 Cobalt Grid**

- 一次真实资格结果正好为 8 页，匹配本次展示长度。
- 生成、跨页编辑、保存重开和两种导出均通过。
- 资格问题清单中没有记录 Cobalt Grid 专属阻断问题。

**仍未验证**

- 外部真实用户是否有同样需求。
- 是否显著节省制作时间或减少返工。
- 5 个模板的长期、重复稳定性。
- 不同电脑、系统环境和更多材料的兼容表现。

**画面建议**

左侧为五模板资格矩阵，右侧为“已验证 / 未验证”边界。不要用百分比包装一次性验收。

## 第 8 页｜结论：把不确定的 AI 输出，变成可验收的产品流程

**用户价值**

从一份中文项目材料出发，在同一产品中完成生成、修正、保存、重开和交付。

**产品经理价值**

- 从真实问题出发，明确首个用户与唯一场景。
- 通过范围取舍，把大想法压缩为一周可展示的完整闭环。
- 用原型、纵向切片、人工反馈和双轨测试逐步降低风险。
- 用领域文档、ADR、GitHub Issues、验收记录和事实边界让决策可追溯。

**现场演示动作**

打开这份项目 → 修改一处文字 → 移动一张普通内容图片 → 保存 → 返回首页并重新打开 → 导出 PDF。

**下一步**

完成这份真实材料的全链路运行记录，保留耗时、人工修改点、失败与恢复情况；之后再建立旧流程基线，并邀请目标用户完成任务测试。

**收束句**

我做的不只是一个会生成页面的 AI 工具，而是一条让用户敢于把真实材料交给 AI、并能把结果继续用下去的工作流程。

**画面建议**

以“真实材料 → 可信交付”大箭头收束，底部放置六步现场演示清单，作为演讲结束后立即开始操作的过渡页。
