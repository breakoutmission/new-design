## 问题陈述

首个用户能用本产品把中文材料生成演示文稿并轻量编辑，但演示文稿的 HTML 文件一旦离开生成工具——无论是本产品导出的，还是其他 AI 工具产出的——用户就没有安全的继续修改方式：直接改 HTML 需要编程知识，随手用别的工具打开又可能毁掉版式或引入安全风险。用户需要一个入口：上传一个简单的 HTML 演示文稿，先弄清它能否被安全编辑，再像编辑 PPT 一样修改文字、图片和基础排版，最后保存或导出。

## 解决方案

在现有应用中新增「导入演示」：用户上传单个自包含 HTML 文件 → 系统逐条规则执行导入检查并展示报告 → 判定为「完全可编辑 / 部分可编辑 / 暂不支持」三档 → 前两档创建演示项目，并沿用既有的安全预览 → 编辑 → 保存 → 重新打开 → 导出（HTML/PDF）链路。编辑器扩展为支持：文字内容就地编辑与七项排版（字体、字号、颜色、粗细、行距、字间距、对齐方式）、文本框整框拖拽（流式布局下原位留白）、图片移动与四角等比缩放与替换、元素复制与删除、会话内撤销/重做。导入副本移除全部脚本、CSS 动效转为静态；暂不支持的文件只展示报告、不创建项目；原始上传文件不被修改。受限范围与数据模型决定见 ADR-0013。

## 用户故事

1. 作为首个用户，我想在首页找到「导入演示」入口，以便把外部 AI 生成的 HTML 演示文稿交给产品处理。
2. 作为首个用户，我想一次选择一个 .html 文件上传，以便不用理解压缩包或文件夹结构。
3. 作为首个用户，我想在上传后看到逐条规则的导入检查报告，以便知道这份文件能被编辑到什么程度、为什么。
4. 作为首个用户，我想看到三档判定结果（完全可编辑 / 部分可编辑 / 暂不支持），以便决定是否进入编辑。
5. 作为首个用户，当文件被判为暂不支持时，我想看到明确的原因清单且不产生项目记录，以便修正文件后重新上传。
6. 作为首个用户，当文件判为部分可编辑时，我想在报告里看到哪些内容会被锁定，以便预期能改什么、不能改什么。
7. 作为首个用户，我想让带 CSS 入场动画的文件被转为静态显示，以便这类文件尽量进入可编辑档而不是被拒绝。
8. 作为首个用户，我想让导入副本移除脚本并由产品提供翻页，以便文件里的代码不会干扰编辑或安全。
9. 作为首个用户，我想确认导入后原始上传文件未被改动，以便放心反复尝试。
10. 作为首个用户，我想让通过检查的导入项目出现在首页项目列表、项目名为文件名（去掉 .html），以便和生成的项目一样管理。
11. 作为首个用户，我想先进入安全预览浏览导入的演示，再主动进入编辑，以便获得和生成项目一致的体验。
12. 作为首个用户，我想通过上一页/下一页、页码和键盘方向键在页面间切换，以便逐页检查内容。
13. 作为首个用户，我想点击选中可编辑文字并就地修改内容，以便快速改正错别字和文案。
14. 作为首个用户，我想调整文字的字体、字号、颜色、粗细、行距、字间距和对齐方式，以便微调版式。
15. 作为首个用户，我想拖拽移动整个文本框，且流式布局下原位置留白、周围内容不回填，以便像 PPT 一样自由排版。
16. 作为首个用户，我想拖动图片位置并用四角控制点等比例缩放，以便调整图片布局。
17. 作为首个用户，我想用本地图片文件替换现有图片内容，以便更新配图。
18. 作为首个用户，我想复制和删除可编辑文字与图片元素，以便快速重复版式或移除多余内容。
19. 作为首个用户，我想对以上全部编辑操作逐步撤销和重做，以便放心尝试。
20. 作为首个用户，我想点击保存并看到无需确认的短暂成功提示，以便确认修改不会丢失。
21. 作为首个用户，我想返回首页后重新打开导入项目继续编辑，以便跨会话工作。
22. 作为首个用户，我想导出修改后的 HTML 且允许保留 https 图片链接，以便在浏览器中继续使用。
23. 作为首个用户，我想导出 PDF，以便交付定稿。
24. 作为首个用户，我想让锁定元素保持原样显示、点击时得到明确的不可编辑提示，以便理解什么不能改。
25. 作为首个用户，我想让导入项目不出现「重新生成」入口，以便不会被要求提供不存在的源材料。

## 实现决定

- 遵循 ADR-0013（解除导入暂缓 + 受限形式）、ADR-0009（GrapesJS 项目数据是唯一编辑状态载体，HTML 是导出成果）、ADR-0010（GrapesJS 是唯一编辑引擎）、ADR-0007（严格沙箱预览）。
- 新增「导入检查器」独立模块，作为纯函数缝：HTML 字符串输入，输出判定档位、逐条规则报告和处理后的 HTML。不为导入另建自定义幻灯片数据模型，导入项目与生成项目共用同一份 JSON 项目记录结构与保存/重开/导出链路。
- 页面识别为带优先级的启发式规则清单（如 class 含 slide/page 语义的容器、多个固定尺寸或全屏的顶级区块，全部失败则回退单页或判暂不支持）；规则清单与每条规则的正反样本在实现 Issue 中固化。
- 三档判定映射：完全可编辑 = 识别出页面且内容均为静态文字、普通图片和基础样式；部分可编辑 = 识别出页面但存在锁定内容（如 SVG 装饰、背景图、特殊布局）；暂不支持 = 识别到 React/Vue、Canvas/WebGL、iframe、内容由脚本生成、识别不出页面或文件畸形/超大。
- 导入处理步骤：移除全部脚本（内联与外部引用），CSS 动画与过渡转为静态（脚本驱动的动效不处理，按暂不支持或锁定判定），随后进入与生成项目相同的安全预览 HTML 准备流程。
- 新增上传接口：接收单个 .html 文件（设大小上限），返回导入检查结果；仅完全可编辑与部分可编辑两档创建演示项目。项目 JSON 记录新增来源类型、原始文件名、导入检查报告与档位字段；原始上传文件另存只读副本。
- 编辑器扩展：文字新增复制、删除、整框拖拽（流式布局下转为自由定位并在原位放置占位以留白）与字体、粗细、字间距三项排版（补齐既有的字号、颜色、行距、对齐）；图片新增替换（本地图片读入为内嵌数据）；锁定元素交互沿用现有「不可编辑提示」。
- 导出放宽仅作用于导入来源的项目：HTML 导出允许保留 https 图片链接，仍禁止本地 file:// 与脚本；PDF 导出流程不变。
- 撤销/重做沿用编辑器现有撤销管理器，仅限当前编辑会话。

## 测试决定

- 好测试只测公开外部行为，不测内部函数名与实现细节；以「能否从公开界面完成用户任务」为验收口径。
- 只用两条测试缝：① 公开浏览器行为——从真实界面上传样本、查看报告、进入编辑、修改、保存、重开、导出（现有公开界面浏览器测试体系为先例，验收主战场）；② 导入检查器模块缝——直接输入 HTML 字符串、断言档位与报告，用固定 HTML 样本覆盖每条规则的正反例与组合，使规则表可快速迭代。除这两条不再新增其他缝。
- 为页面识别与三档判定准备固定样本集（含本产品导出的 HTML、典型 AI 工具输出形态、含脚本/框架/Canvas 的反例），作为可回放的固定测试材料；对外兼容性声明以样本集通过为准。
- 导出回归：导入项目导出的 HTML 允许 https 图片且可离线打开翻页；PDF 页数与页面尺寸检查沿用现有做法。

## 范围外

React/Vue 等框架页面、Canvas/WebGL、iframe、复杂或脚本驱动动画、3D、大量依赖脚本动态生成的内容；文件夹/压缩包/多文件上传；新增文字框或图片；页面增删与排序；图层列表；多选批量操作；修改页面尺寸；跨会话撤销历史；脚本驱动动效的转静态；不承诺兼容所有 AI 工具的输出（以样本集验收为准）。

## 进一步说明

- 导入入口在首页的摆放需与进行中的 UI 重构 Issue #11 协调，避免对首页重复改动。
- 文本框拖拽已拍板为「原位留白」：若实现中证明成本失控，回到用户重新权衡，不默默降级为「回填」。
- 证据边界：本 Spec 发布时功能状态为 PLANNED；仅在验收通过后才可在证据库记录为 VERIFIED。
- 拆票建议：第一张票为纵向子弹（上传 → 检查 → 报告 → 打开编辑），先固定上传接口契约与报告 JSON 结构；其后后端向（检查器规则、导出放宽）与前端向（报告页、编辑器扩展）可并行推进；改动尽量收敛到各自新模块，跨既有文件的改动集中处理以减少并行冲突。
