# 一周 MVP 使用完整 HTML 生成契约

一周 MVP 要求 Codex 为每次生成请求返回一份完整、自包含的 HTML 演示文稿，而不是只返回结构化幻灯片内容。生成结果必须同时遵守所选演示模板的提示、示例 HTML 和产品统一生成约束，并在通过页面结构、可编辑标记和安全能力检查后，才能进入安全预览和 GrapesJS 编辑流程。

这个阶段性选择优先保证一周内可以展示完整链路。Grove 原型已经证明：完整 HTML 可以经本机 Codex 生成，进入 GrapesJS 后完成文字和普通内容图片编辑，保存并重新打开项目编辑状态，以及导出可独立翻页的 HTML 和多页 PDF。沿用这条已验证路径，比首周同时设计结构化内容格式和模板填充系统更能降低集成风险，并保留五个演示模板各自的视觉与版式体系。

该方案的代价是生成较慢、Token 用量较高，并且模型输出可能出现结构漂移。Grove 的一次真实原型运行耗时约 3 分 45 秒，Codex 报告 186,633 个累计输入 Token，其中 141,056 个为缓存输入，另有 10,873 个输出 Token。这些数值只作为原型诊断证据，不是固定性能承诺，也不能直接换算为账单金额。日常浏览器测试因此使用固定生成夹具，真实 Codex 只用于五个模板的资格验收和最终真实材料演示。

MVP 之后可以另行决定迁移到“小型结构化内容 + 应用填充固定模板”的生成契约，以减少重复输出模板 HTML 带来的延迟、Token 用量和格式漂移。迁移前需要先定义能够表达五个模板所需内容的结构、模板填充规则和已有项目的兼容方式；本 ADR 不提前规定该后续格式。
