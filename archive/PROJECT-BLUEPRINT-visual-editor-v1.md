# FineCanvas 产品项目路线图（暂定名）

> 这是整个项目的导航图，不要求一次做完。当前只执行“第 1 步：锁定问题与 MVP”。

## 1. 产品定义

**一句话定位**

FineCanvas 是给不懂代码、但经常使用 AI 生成页面的产品经理和内容创作者使用的轻量编辑器：导入或从模板生成 HTML 后，可以像编辑海报一样直接修改文字、图片和留白，并导出可交付的 HTML。

**核心 Job To Be Done**

当 AI 已经生成了一个基本可用的页面，但细节不符合预期时，我希望不用反复写提示词或改代码，就能直接完成最后 20% 的调整并交付。

**为什么不直接 fork 完整 Open Design**

Open Design 当前是“Web 应用 + 本地 daemon + 多种 Agent + Skill 注册表 + Artifact 存储 + 导出管线”的平台型架构。它也已经具备实时参数、评论式修改、人工编辑检查器、上传和删除元素等能力。直接缩改整仓库会让新手把时间消耗在运行环境与平台代码，而不是完成一个清晰产品闭环。

我们的策略是：借鉴它的模板、Skill 和真实 HTML 产物理念；重新做一个只解决“生成后微调”的小产品。

## 2. 目标用户与场景

**第一目标用户**：不会写前端代码，但会用 ChatGPT、Claude 或 Codex 生成 HTML 的初级产品经理、运营和内容创作者。

**首个场景**：制作产品介绍页、活动页或项目展示页，AI 已完成约 80%，用户需要修改文案、图片比例、模块间距和顺序。

**暂不服务**：专业 UI 设计师、复杂网站开发者、多人设计团队、视频与三维创作者。

## 3. MVP 范围

### P0：必须真的可用

1. 从 3 个固定模板中选择一个，或粘贴一段 HTML。
2. 点击文字后直接修改。
3. 选中图片后替换图片，并修改宽高或裁切方式。
4. 选中模块后调整内外间距。
5. 拖动模块改变上下顺序。
6. 撤销、重做和恢复初始版本。
7. 自动保存到浏览器本地。
8. 导出 HTML/CSS 文件。

### P1：MVP 验证后再做

- 通过简短表单生成模板内容，而不是让 AI 自由生成任意结构。
- 加入一个 Open Design 风格的轻量 Skill 清单和统一输入协议。
- 接入一个真正可运行的外部 Skill，并记录输入、输出与失败状态。
- 分享只读预览链接。

### P2：作品集加分项

- `ppt-master` 作为独立的“生成演示文稿”工作流接入，共享项目内容和素材库。
- 设计规则检查：溢出、低对比度、图片失真、间距不一致。
- 修改前后对比、版本历史和一键回滚。

### 明确不做

- 第一版不做多人协作、登录、支付、移动端编辑、任意自由画布。
- 第一版不让 `ppt-master` 生成的 PPTX 在 HTML 画布里直接编辑；两者输出结构不同。
- 第一版不承诺兼容任意互联网页面，只支持我们的模板和受控 HTML。

## 4. 推荐技术方案（新手友好）

| 层 | 选择 | 原因 |
|---|---|---|
| 产品外壳 | Next.js | 文档完善，AI 编码工具熟悉，便于部署 |
| 可视化编辑器 | GrapesJS Core | 已有拖拽、组件树、样式和导出能力，不自研画布 |
| 数据保存 | 浏览器 IndexedDB 或 localStorage | MVP 不需要后端、账号与数据库 |
| 模板 | 3 个自有受控 HTML 模板 | 可保证编辑和导出稳定，便于测试 |
| 部署 | Vercel 或静态部署 | 便于向面试官分享链接 |
| AI/Skill | 第二阶段做轻量适配器 | 先完成编辑闭环，再加入复杂运行时 |

## 5. 六阶段计划

### 阶段 A：问题验证（3–5 天）

- 用同一任务实测 Open Design：生成页面、改文案、改图片、改间距、改模块顺序、导出。
- 访谈 5 位会用 AI 生成页面但不会前端的人。
- 输出：竞品任务表、访谈记录、问题优先级、MVP 版本 1。

**通过条件**：至少 3/5 人真实遇到“生成后小改很费劲”，并且愿意尝试直接编辑工具。

### 阶段 B：交互原型（3–4 天）

- 只画 4 个界面：项目首页、模板选择、编辑器、导出成功。
- 用静态页面或设计工具做可点击原型。
- 找 3 人完成任务测试，记录卡点。

**通过条件**：3 人中至少 2 人无需口头指导，能完成修改文字、图片和间距。

### 阶段 C：可运行 MVP（2–3 周）

- 使用 Next.js + GrapesJS 实现 P0。
- 每完成一项功能就做一个可观察的验收任务。
- 每周保留运行视频、截图、问题清单和版本说明。

**通过条件**：用 3 个模板各完成一次完整编辑与导出，刷新页面后内容仍在。

### 阶段 D：Skill 试点（1 周）

- 定义最小 Skill 协议：名称、说明、输入字段、输出类型、运行状态。
- 只接入 1 个能真实运行的 Skill。
- `ppt-master` 先作为独立输出管线验证，不强行塞进 HTML 编辑器。

**通过条件**：用户可选择 Skill、提交输入、看到运行结果或明确错误，并能重复成功。

### 阶段 E：用户测试与迭代（1 周）

- 让 5 位用户完成固定任务，记录成功率、耗时、求助次数、放弃点。
- 只修复最高频、最高阻塞的问题。
- 输出版本对比和取舍记录。

### 阶段 F：面试作品集（2–3 天）

- 3 分钟 Demo：问题 → 生成/导入 → 直接编辑 → 导出。
- 8 页案例：背景、研究、问题、取舍、方案、开发、测试、反思。
- GitHub README：运行方式、功能、架构、已知限制、路线图。

## 6. 面试官真正会看的证据

- 你为什么删掉 80% 的功能，而不是做了多少功能。
- 用户证据如何改变需求优先级。
- 功能是否能现场稳定跑通，而不是只有高保真原型。
- 你如何定义验收标准、处理失败、记录迭代。
- 你能否区分“自己判断”“用户反馈”“AI 写的代码”和“真实结果”。
